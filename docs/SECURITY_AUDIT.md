# Phase 4.2 security audit

## Initial findings

This inventory records the source review before remediation. The log and archive findings cover disclosure in trusted administrative and release workflows. HTTP findings cover browser-origin trust and safe handling of management inputs. Findings and release evidence are tracked independently.

| ID | Severity | Component and files | Evidence, root cause, and impact | Recommended remediation |
| --- | --- | --- | --- | --- |
| UDP-42-01 | High | Release source archive, `scripts/build-release.py` | The archive enumerates untracked, unignored files and dereferences symlinks with `read_bytes`. A local build can package unrelated private files or files outside the checkout. | Package only tracked source, reject non-regular files, and scan archives before publishing. |
| UDP-42-02 | Medium | Management trust, `internal/httpapi/management_security.go` | Fetch metadata permits same-site requests even when the browser has identified a different origin. Origin and Referer can both be absent. Such requests could read management resources in contexts where browsers allow embedding or fetching, subject to other browser protections. | Require same-origin or direct navigation when fetch metadata is present, while retaining explicit origin validation and proxy trust. |
| UDP-42-03 | Medium | Operational logging, `internal/events/events.go`, `internal/storage/operations.go` | Free-form redaction replaces only a single token after sensitive header names. Credential material after spaces or additional cookies can survive. Older retained rows are exported without a read-side redaction pass. | Strip whole sensitive header values and control characters, redact structured fields, and apply the same rules at export. |
| UDP-42-04 | Medium | Windows installer, `scripts/install-windows.ps1` | The elevated installer accepts pre-existing roots, copies executable content before inspecting the destinations, and preserves unrelated explicit ACL entries. A pre-created directory or reparse point can redirect writes. | Require fresh protected roots for automated install. Apply explicit permissions at creation, preserve existing installations through the upgrade workflow, and test standard-user access. |
| UDP-42-05 | Medium | SQLite backup and restore, `internal/storage/backup.go` | Exclusive creation prevents overwriting an existing leaf, but parent symlinks are followed and the SQLite backup reopens the destination by path. An operator can inadvertently write outside the intended directory. | Reject redirected parent paths, validate the reserved output, and document the trusted-directory requirement for operator-controlled paths. |
| UDP-42-06 | Medium | CI and release, `.github/workflows` | Action major tags are mutable. Candidate validation and release build use different versions, and the release draft job holds a write token. | Verify exact candidate artifacts, pin actions, restrict tokens, and gate draft creation on security and native test results. |
| UDP-42-07 | Low | Management JSON, `internal/httpapi/server.go`, `operations.go`, `streams.go` | Duplicate Content-Type headers are interpreted by the first value. Several JSON decoders collapse a body-limit failure on a second read into a generic malformed response. | Reject ambiguous media types and preserve size errors through shared decoding. |
| UDP-42-08 | Low | Management security headers, `internal/httpapi/server.go` | The existing policies block framing and inline scripts but do not restrict form destinations or disable browser capabilities. | Set form-action and Permissions-Policy on management responses only. |
| UDP-42-09 | Low | M3U export, `internal/playlist/m3u.go`, `internal/stream/channel.go` | The exporter rechecks delimiter characters for old records but does not revalidate logo URL schemes. Imported records are validated on write, but an externally modified or older database can contain unsafe URLs. | Reuse logo URL validation during export and test legacy metadata. |
| UDP-42-10 | Informational | Platform and configuration boundaries | Trusted local users and explicitly configured reverse proxies control management. Allowed UDP source IPs are network filters, not cryptographic source identity. SQLite, package scripts, and backups depend on operating system directory permissions. | Maintain least privilege and record native acceptance, confinement assumptions, and deployment trust boundaries. |
| UDP-42-11 | Medium | Listener resource budgets, `internal/httpapi/server.go`, `internal/httpapi/streams.go` | Header deadlines and viewer limits exist, but neither caps accepted TCP sockets before the application parses or authorizes a request. Open sockets consume per-connection runtime state. | Cap accepted sockets independently of the viewer limit and retain existing read, write, and idle deadlines. |

Audit references include the [OWASP Top 10](https://top10.owasp.org/), [OWASP API Security Top 10](https://api-security.owasp.org/), and [Go security guidance](https://go.dev/doc/security/).

## Remediation and verification

| ID | Implemented fix | Regression or evidence | Final verification |
| --- | --- | --- | --- |
| UDP-42-01 | Release packaging accepts tracked regular files and individually nominated new files. Debian docs use a fixed file list. | Static source ZIP inspection and nested credential-pattern scan. | Passed local artifact inspection. |
| UDP-42-02 | Require same-origin, direct navigation, or a non-browser request without fetch metadata, plus existing Host, Origin, Referer, and proxy checks. | `TestManagementRejectsCrossOriginFetchMetadata` plus the existing proxy/browser policy tests. | Passed in the Windows HTTP API suite. |
| UDP-42-03 | Redact full sensitive headers, secret assignments, and control characters. Sanitize structured retained entries when read. | `TestRedactsEntireSensitiveHeadersAndStoredContext`. | Compiles and vets. Native execution pending. |
| UDP-42-04 | Create protected fresh roots before the first executable or configuration write. Require administrative ownership of installation and LocalService access scoped to its data/log locations. | PowerShell parse and native installer assertions for ACLs, identity, quoting, and version metadata. | Syntax checked. Native Windows gate pending. |
| UDP-42-05 | Resolve parent directories, reject redirected paths, require new files, and confirm SQLite used the reserved destination. | `TestBackupDestinationRejectsLinkedParent` and `TestOnlineBackupVerifyRestoreAndNoOverwrite`. | Compiles and vets. Native storage tests pending. |
| UDP-42-06 | Pin trusted action commits and promote only the immutable candidate artifacts exercised by the native matrix. | Workflow review, static CLI/checksum validation, release-only draft approval. | Local static checks passed. Hosted workflow run pending. |
| UDP-42-07 | Reject duplicate Content-Type and JSON names, null documents, extra documents and malformed fields. Preserve request-size errors. | `TestStrictManagementJSON` and proxy mutation tests. | Passed in the Windows HTTP API suite. |
| UDP-42-08 | Disable browser capabilities and restrict form destinations. Management headers stay scoped to management. | Security-header assertions and production assets under the daemon’s browser policies. | Passed in the Windows HTTP API suite and the live Edge smoke test. |
| UDP-42-09 | Recheck stored logo URLs during M3U generation before writing playlist output. | `TestExportRejectsUnsafeStoredLogo` and existing import tests. | Compiles and vets. Native execution pending. |
| UDP-42-10 | Record trusted local-user, proxy, OS, and UDP source boundaries. | [Threat model](THREAT_MODEL.md) and [deployment guidance](SECURITY_HARDENING.md). | Deployment-dependent controls remain applicable. |
| UDP-42-11 | Limit each listener’s accepted TCP sockets independently of application viewer budgets. | Existing integration, load, and graceful shutdown tests cover normal use and cleanup. | Windows HTTP API suite and 1–100-viewer runtime checks passed. Native Linux performance verification is pending. |

## Manual review coverage

- **Management API.** Read routes cover health, status, interfaces, CSRF, dashboard, metrics, clients, system, logs and log export, playlist config and download, stream snapshots and status, and diagnostics. Changes go through channel create/update/delete and actions, bulk changes, import preview/commit, client disconnect, diagnostics POST, and settings validate/save/rollback. Review covered browser trust, per-endpoint method handling, JSON validation, limit handling, and revisions.
- **Browser.** React renders channel names, log text, and metadata as text. Local storage holds theme and sidebar preferences. Playlist URLs are constructed from validated configuration and encoded selectors. Channel logos are never rendered or fetched by the management UI. Diagnostic downloads use local blob URLs. The new external link uses a static HTTPS URL and opener isolation.
- **Receive and fan-out.** Review covered literal IPv4 addresses, reserved multicast, interface and destination packet filtering, explicit loopback permission, peer CIDRs, startup and idle deadlines, TS framing, connection and queue limits, shared receiver lifecycle and recovery, and direct HTTP listener boundaries.
- **Persistence and installation.** Reviewed bound SQL parameters and schema/user-version handling, transaction/write conflicts, backups, restore paths, owner-only state, service ACLs and systemd controls.
- **Supply chain.** Reviewed dependency locks, esbuild’s postinstall, source selection in archives, artifact metadata and integrity, and workflow privileges. Before stable promotion, review the hosted CodeQL, Gosec, and Gitleaks results and native runtime output.
