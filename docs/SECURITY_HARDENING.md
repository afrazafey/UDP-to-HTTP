# Security hardening

- Keep management bound to `127.0.0.1:8080`. If an Nginx proxy is required, configure exact trusted proxy addresses and origins. Keep the Nginx client allowlist, authentication, and overwritten forwarding headers together. Restrict playback separately. [Nginx deployment](../deploy/NGINX.md)
- The management listener accepts at most 64 simultaneous TCP connections. Each playback listener permits the configured viewer cap plus 32 connections for negotiation and idle sockets. The manager still enforces the configured total viewer cap across playback listeners.
- Keep a dedicated service account and private state directory. Debian config is installed as a conffile, then restricted to `root:udphttp-proxy` mode 0640 by the maintainer script. The service state directory is 0700, the executable is 0755, and the unit file is root-owned and 0644.
- The systemd unit keeps `AF_NETLINK` for interface discovery and `AF_INET` for IPv4. It preserves `AF_UNIX` and `AF_INET6` for supported runtime operations. Kernel-log and clock protection and the native system call architecture are added. The existing 0077 umask is stricter than 0027. `PrivateDevices=true` limits device access. General syscall and memory-execution filters require native tests before adoption. [systemd execution options](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)
- Keep backup and restore destinations in directories controlled by the operator, with regular files and no redirected parent paths. Verify a snapshot before switching the configured database path. The CLI restore requires a fresh destination and explicit offline confirmation.
- Use the Windows fresh installer only on a clean destination. It verifies protected ACLs before writing the executable or config. LocalService can read config and modify only its state and log paths in the install tree. Inspect pre-existing installations with `icacls` and follow the upgrade instructions. Release PE resources are separate from Authenticode signing.

Native Debian validation records both `systemd-analyze security udphttp-proxy.service` reports, then checks HTTP playback, conffile preservation, and service lifecycle. The score is an indicator of service sandbox exposure and is considered alongside successful playback.
