# Security and trust model

Management binds to a literal IPv4 loopback address (default 127.0.0.1:8080); remote binding is rejected. Local users/processes are trusted administrators. There is no native remote account/session/password system. Request peer, Host/port, Origin, Referer and browser fetch metadata are checked before routing, including static assets. Mutations need a per-process random token from GET `/api/v1/csrf`, a single `X-CSRF-Token`, exact `application/json`, a body up to 1 MiB and the global write-rate budget. Tokens are not authentication credentials for remote users.

Use `ssh -N -L 8080:127.0.0.1:8080 ADMIN@SERVER`, then browse the local forwarded address. Restrict SSH access independently. Forward playback separately if needed. Do not open the management listener in a firewall or add a wildcard management bind.

Existing optional same-host management reverse-proxy support stays disabled by default. It trusts only configured literal loopback TCP peers and exact configured external origins with strict scheme/host/port spelling. Complete single-valued X-Forwarded-Host/Proto/For headers are required, with an optional agreeing Port. Arbitrary forwarding/identity headers, duplicates, chains, malformed values and cross-origin requests are rejected. Direct local requests still require local Host/origin. This does not authenticate a proxy's users: Nginx must enforce authentication, TLS and IP authorization on **all** HTML/assets/API/token paths. Local processes sharing a trusted proxy address retain the existing local-administrator privileges. See the earlier explicit design in [deploy/NGINX.md](../deploy/NGINX.md); its HTTP-only LAN example is not a production TLS acceptance result.

Playback listeners enforce actual-peer IPv4 CIDRs; empty lists deny everyone. Never trust forwarded IPs to bypass this rule. Remote playlist exposure is off by default and requires an additional explicit CIDR policy and advertised host; both playlist and playback client policies apply. Playlists can reveal enabled channel names/logos/URLs to allowed clients, so retain local-only export unless this is intended.

Every source remains a literal validated IPv4/port on an actual selected interface. Multicast sources need exact allowlisting; reserved local-control 224.0.0.0/24 is always blocked, and additional configured exclusions also apply. Unicast sender IPs need exact allowlisting; loopback requires a separate permission. Imports never change these policies. Configurable policies do not imply unrestricted source authorization.

M3U import handles bounded local UTF-8 text, never filesystem names or URL fetching. Only explicit UDP and legacy multicast /udp/ patterns convert to sources. Arbitrary HTTP/HLS/RTP, credentials, query/fragment source URLs, malformed metadata and duplicate identities are rejected. Logo URLs are bounded HTTP(S) metadata; the server never fetches/proxies them and the dashboard does not automatically render them. Review imported logos before giving playlists to external players.

API paths validate channel IDs and use parameterized SQL. Exports validate metadata again against injection. The TS framer bounds incomplete packets and PID state; queue and client/stream counts are bounded. Static serving validates fs paths; APIs do not fall through to SPA content. Security headers/CSP/no-store remain enabled. CSRF/content/size/rate guards cover import, bulk and diagnostic actions.

Diagnostics accept only fixed actions and configured channel IDs/listener addresses. They do not accept arbitrary remote destinations, run shell commands, scan networks or change host settings. HTTP probes use daemon-owned local addresses, disable redirects/proxies and have strict time/header limits. Socket binding, joining and packet receipt are reported separately from decoding/playback success.

SQLite data and backups contain private configuration/history. Linux data directories/files use 0700/0600; Windows installation uses explicit ACLs. Backups reserve a new file and verify integrity/schema/checksum. Restore does not overwrite an existing database and requires explicit offline confirmation. Keep backups private and verify the provenance/checksum before restoring. Do not copy only a live WAL database's main file.

Structured events redact recognized secret keys, bearer patterns, assignment patterns and URL credentials/queries. Packet bodies, Basic credentials, full imported payloads and full configuration requests are not logged. Bounded history is not an immutable audit ledger; dropped events are visible. Diagnostic log exports inherit management authorization.
